### Q1
**Type:** Multiple Choice
**Question:** Dalam penyusunan sistem pertahanan otomatis perusahaan, mengapa spesialis SOC yang berkompetensi mengelola operasi infrastruktur <i>SIEM</i> dan implementasi integrasi taktis <i>IPS</i> (Contoh penerapan Suricata) dianggap mengemban tanggung jawab dan kompleksitas kualifikasi yang lebih krusial?
- [x] A. Karena kapasitas Analis SOC Tingkat Lanjut (sebagai perekayasa *Threat Engineer*) tidak sebatas pelaksana pemantauan diagnostik laporan grafis. Mereka menyusun korelasi penelusuran arsitektur deteksi berantai; menyelaraskan pembuatan peringatan di platform ekosistem *Splunk (SIEM)* untuk visibilitas, lalu disusul pengaturan implementasi instruksi penolakan teknis (*Rule Drop*) ke titik perimeter sensor kontrol operasi detektor instruksi jaringan <i>Suricata (IPS)</i> untuk memblokir mitigasi krisis insiden koneksi secara terprogram.
- [ ] B. Karena spesialis operasi pelaporan SIEM mutlak dilarang menyentuh perancangan implementasi penolakan sistem <i>Rule IPS</i>.
- [ ] C. Parameter lisensi kualifikasi pemantauan pelaporan dari manajemen platform *Splunk* disinyalir bersinggungan langsung pemanfaatan taktis serangan *Ransomware*.
- [ ] D. *Threat Engineer* menolak parameter ekosistem SIEM dan mendayagunakan filter sintaks manual `awk` secara eksklusif.

### Q2
**Type:** True/False
**Question:** Pada analisis kueri investigasi *SIEM Splunk*, operator analis merangkaikan fungsi seleksi filter pencarian status kriteria <i>EventCode 4625</i> digabungkan bersama <i>Logon_Type 10</i>, lantas memproses lanjutan ekstraksi temuan via struktur sintaks ke modul manipulasi lanjutan agregat <i>stats count by src_ip</i> guna memastikan validasi rumusan skema indikator konklusi peretasan otentikasi eksploitasi (*Brute Force Remote*) melalui konektivitas protokol Windows RDP.
**Answer:** True

### Q3
**Type:** Short Answer
**Question:** Saat mengeksekusi parameter pengolahan bahasa kueri pencarian informasi <i>Splunk</i>, fungsi sisipan sintaks kueri tambahan `table _time, src_ip, uri` diintegrasikan dalam parameter pencarian dengan teknis keluaran (output) spesifik ditujukan sebagai parameter perubahan wujud presentasi teknis seperti apa?
**Answer:** Parameter pemrosesan visualisasi berwujud tata kelola data berbentuk arsitektur baris dan tabel yang dikategorisasikan secara rapi (terurai khusus spesifik dalam struktur 3 nilai kolom utama taktis: stempel waktu Waktu, metrik nilai IP Asal, serta rute ekstraksi URI log).

### Q4
**Type:** Short Answer
**Question:** Ketika seorang analis merancang perumusan parameter instruksi pertahanan struktural di aturan deteksi peladen (*Rule Sensor*) di sistem kontrol peringatan jaringan seperti modul arsitektur penanganan peretasan *Suricata/Snort IPS*, instruksi modifikasi teknis apakah yang mutlak dikonfigurasikan di argumen awalan pengaturan konfigurasi apabila analis teknikal bermaksud menginstruksikan mitigasi blokir (pencegahan/eksekusi penghentian) pemuatan koneksi transaksi paket serangan taktis?
**Answer:** Instruksi deklarasi parameter teknis pemblokiran penghentian taktis interaktif `drop` (Bukan sekadar operasi deteksi notifikasi pasif pelaporan analitik arsitektur pencegahan peringatan `alert`).

### Q5
**Type:** Short Answer
**Question:** Pada rutinitas pemantauan metrik agregat data lalu lintas insiden SIEM, jika operator kueri menyertakan instruksi parameter argumen restriktif analitikal (seperti pengaturan spesifik kueri rumusan matematis pelaporan pengecualian kondisi khusus agregat kalkulasi sintaks kondisi spesifik) berbunyi `where count > 20` pada rangkaian tata instruksi modifikasi pemilahan SPL *Splunk* (setelah kalkulasi agregat dasar kalkulasi *stats count*), klasifikasi taksonomi elemen modifikasi penyetelan pengaturan batasan nilai batas aktivasi kondisi taktis seperti apa?
**Answer:** Klasifikasi parameter indikator arsitektur pengaturan aktivasi nilai Pemicu Kondisi peringatan teknikal taktis atau penamaan elemen *Trigger Condition (Threshold batas)*.
