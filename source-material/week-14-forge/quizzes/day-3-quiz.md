### Q1
**Type:** Multiple Choice
**Question:** Di ranah perancangan arsitektur keamanan siber peladen aplikasi, ketika menyandingkan dua entitas kasta fungsi benteng pelindung verifikasi *backend*, bagaimanakah uraian teknikal perbedaan spesifikasi pembatasan peran wewenang arsitektur *Otentikasi (Authentication)* bila diadu berhadapan silang secara logik dengan perisai *Otorisasi (Authorization)*?
- [x] A. Otentikasi (*Authentication*) didapuk dan difokuskan bertugas spesifik untuk memverifikasi dan menyaring pembuktian absahnya identitas wujud pengguna pendaftar (menjawab tantangan validasi parameter: "Siapakah Anda sesungguhnya?"). Selagi sistem *Otorisasi (Authorization)* memegang fungsi kontrol mutlak dan penegakan batasan jaring wewenang hak akses (mengevaluasi validasi parameter kondisi: "Benar, profil Anda tervalidasi sebagai agen jaringan terdaftar yang sah, namun apakah arsitektur profil jabatan identitas Anda tersebut dikonfigurasi murni sah dan mutlak berhak merambah serta berwenang mengakuisisi rute akses direktori rahasia data aplikasi spesifik yang barusan Anda interupsi ini?").
- [ ] B. Fitur perlindungan Otorisasi (*Authorization*) berfokus spesifik untuk memverifikasi absahnya keberadaan referensi parameter nilai pengikatan log payload memori penempatan pada tabel database *Backend SQL Server Logic Control Data Persistence Function Integration Method Request Implementation Security Validation Structure Application Data Routing Application Verification Form*, sementara entitas pengikatan *Otentikasi (Authentication)* murni diandalkan untuk mengontrol serta mengatur deklarasi sintaks validasi eksekusi kueri operasional barisan perutean kueri SQL peladen `JOIN` peladen data *Endpoint*.
- [ ] C. Secara definitif dan logik operasional perutean arsitektur aplikasi jaringan tidak ada sedikit pun beda penyelarasan wewenang teknikal di antara keduanya. Entitas *Otorisasi* maupun fungsi sirkuit perutean arsitektur *Otentikasi* sepenuhnya adalah dua frasa pelaporan sinonim murni untuk mendeskripsikan secara teknikal klasifikasi pelaporan pengamanan fungsi intervensi aplikasi atas bahaya kerentanan ancaman jaringan operasi arsitektur peladen manipulasi sandi perutean peretasan rute serangan *XSS Backend Server Protection Module Database Control Application Memory Security Interface SQL Protection Injection Function Interface XSS Architecture Router Implementation Database Vulnerability* secara.
- [ ] D. Keduanya hanya sebatas merupakan dua sebutan ekstensi pelengkap paket dependensi antarmuka peranti penyaringan fungsi kontrol pengamanan skrip kueri spesifik pencegah operasional bahaya interupsi infeksi injeksi *SQL Injection* pada operasional peladen belaka.

### Q2
**Type:** True/False
**Question:** Penyakit kerentanan eksploitasi parameter objek *IDOR (Insecure Direct Object Reference)* niscaya menjangkiti integritas otorisasi perutean *API Backend* ketika arsitek sistem peladen terlalu naif mempercayakan pendelegasian keputusan logik peruteannya dan mematuhi secara membuta murni operasional parameter modifikasi pengikatan angka sandi argumen dinamis (laksana parameter *endpoint* id) di ujung alamat penelusur URL rute klien (semisal membiarkan fungsi di lajur rute spesifikasi masukan URI `/api/pesanan/7`) untuk lantas menyedot secara pasrah dan langsung menyerahkan ekstrak pengunduhan bungkusan data konfidensial database operasionalnya semata-mata bergantung dari variabel URI id tangkapan tersebut secara murni logik mentah penelusuran, tanpa peduli mendelegasikan merakit arsitektur parameter pengecekan validasi otorisasi dobel (yakni verifikasi mengikat pelacakan pencocokan menyilang dengan menyelaraskan payload URI `7` tadi untuk ditubrukannya menelusuri penyesuaian kelayakan otoritas referensi spesifik pemilik asli payload pesanan log id data yang dipanggil ke nilai identitas profil sandi token id sesi rahasia arsitektur *login/JWT payload data request bearer authorization user id interface parameter authentication property logic session access authorization* klien pengakses pemanggil sirkulasi eksekusi pengunduhan rute jaringan aplikasi log arsitektur jaringan operasional peladen tersebut).
**Answer:** True

### Q3
**Type:** Short Answer
**Question:** Apakah penjabaran akronim rincian kepanjangan dari nomenklatur teknikal arsitektur wabah kerentanan fungsionalitas aplikasi kelalaian pengamanan verifikasi otorisasi sandi pengikatan parameter akses manipulasi objek pemanggilan URL rute bertitel inisial id penamaan *IDOR* (yang kerap kali diklasifikasikan secara statistik OWASP didapuk selaku parameter juara penyebab celah kerentanan aplikasi API jaringan web operasional masa kini yang paling ditakuti arsitek *backend software system database integration implementation function parameter logic application logic access architecture*)?
**Answer:** Insecure Direct Object Reference.

### Q4
**Type:** Short Answer
**Question:** Selain pelafalan terminologi teknikal klasik luhur usang semacam klasifikasi akronim peramban fungsi parameter *IDOR*, nomenklatur standar taksonomi sebutan tajuk pembaruan pengklasifikasian standar mutakhir apakah (direpresentasikan oleh singkatan teknis klasifikasi berawalan empat rincian huruf log referensial B) yang di masa arsitektur peramban operasional standar API kini semakin terbiasa lazim dan masyhur diadopsi serta digaungkan klasifikasinya di kalangan konsorsium ahli audit keamanan penetrasi spesialis peretas jaringan pengujian sistem pengerjaan API (*API Security Expert/Penetration Testers*) untuk secara logik dan akurat merujuk mendedikasikan pelaporan pemetaan fungsi identitas pelaporan pada celah ketiadaan perlindungan fungsi otorisasi peladen sistem celah fatal atas manipulasi objek fungsi modifikasi argumen rute variabel URI payload parameter wewenang akses perutean identitas pengikatan referensial spesifik fungsi yang bolong perisainya itu?
**Answer:** BOLA (Broken Object Level Authorization).

### Q5
**Type:** Short Answer
**Question:** Menilik penjabaran pemetaan tata urutan fungsi peringkat hierarki bahaya kerentanan insiden jaringan parameter operasi arsitektur di buku kitab pedoman keamanan global *OWASP Top 10 Web Application Security Vulnerabilities Framework Component Reference Documentation API Security Guidelines Application Logic Protocol* rilisan versi edisi spesifikasi mutakhir abad dekade kini, rumusan pengklasifikasian klasifikasi rumpun jenis kategori kerentanan absolut pelaporan jaringan manakah (di dalam cakupan kerangka taksonomi kategori ini sendiri pun celah fungsi bahaya eksploitasi parameter objek *IDOR/BOLA* diklasifikasikan mutlak berdiam menaungi bernaung memayungi fungsionalitas kategorisasinya di lingkup kategori ini secara teoretikal standar klasifikasi keamanan jaringan API) yang secara menakutkan mendominasi klasifikasi parameter mencengkram dan menduduki teguh fungsionalitas posisi takhta kehormatan statistik pelaporan pemetaan arsitektur rentan di peringkat Nomor Satu (kategori paling mendominasi bahaya serangannya berulang dan terganas ancamannya saat perutean rilis API global *Web Backend Node API Architecture System Developer Security Assessment Bug Database Form Backend Vulnerabilities API Integration Network Application*)?
**Answer:** Broken Access Control (BAC).
