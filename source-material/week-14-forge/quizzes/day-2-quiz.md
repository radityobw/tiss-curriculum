### Q1
**Type:** Multiple Choice
**Question:** Membandingkan peta demarkasi serangan mematikan *SQL Injection* dan *XSS*, jurang filosofis target korban apa yang secara telak mencerai sasaran utama dari kedua serangan operasional tersebut?
- [x] A. Target eksploitasi peretasan *SQL Injection* terfokus mutlak pada penetrasi dan penguasaan infrastruktur peladen belakang *Backend* (sistem basis data/Database server). Sebaliknya, injeksi serangan modifikasi parameter memori *XSS* menyasar operasi eksploitasi serangan langsung ke sisi antarmuka pengguna di sisi klien penelusur peramban (*Frontend Browser*), dengan spesialisasi objektif memanipulasi peladen antarmuka guna memaksa peramban pengunjung patuh mengeksekusi kerangka skrip payload tersembunyi *JavaScript* berbahaya yang sukses diselundupkan dan disisipkan oleh pihak penyerang tanpa sepengamatan sistem otorisasi pengguna.
- [ ] B. *SQL Injection* hanya dirancang murni spesifik untuk menyerang struktur memori arsitektur tak berskema seperti tipe peladen memori jaringan portabel MongoDB; sementara penyerangan *XSS* diciptakan spesifik murni meretas tabel SQL relasional.
- [ ] C. Operasional payload *XSS* menjangkit infeksi serangannya masuk memori sistem merusak struktur piranti lapisan piringan cakram *harddisk* fisik server, sementara jangkauan serangan eksploitasi eksekusi manipulatif algoritma sandi rute *SQL Injection* sekadar bermanifestasi melintas merusak eksekusi ruang RAM penahanan fungsi memori awang sementara komputer jaringan semata.
- [ ] D. Tidak ada pembeda parameter struktural apa pun, keduanya seragam murni meretas memori lewat pengelabuan fungsi eksploitasi rute pengalihan jaringan komando perutean metode jaringan spesifik pemusnahan HTTP bertipe operasi pendelegasian instruksional DELETE.

### Q2
**Type:** True/False
**Question:** Di antara faksi tiga varian kasta peretasan Trinitas klasifikasi tipe *XSS*, taktik penyerbuan pengelabuan manipulasi rute peramban *Reflected XSS* dinobatkan menduduki kursi celah kerentanan operasional aplikasi peringkat paling mematikan (sanggup merusak membunuh jutaan komputer seketika secara serentak terotomatisasi) lantaran payload skrip mautnya bakal menetap bernaung mengkristal tersimpan statis kekal terukir berkerak murni di dalam kumpulan penyimpanan arsip sistem memori basis data SQL peladen (*Database Backend*), memicu infeksi transmisi peladen ke seluruh jaringan pengunjung tanpa bahkan pernah lagi membutuhkan instruksi pancingan penipuan manipulasi peramban penekanan eksekutor klik antarmuka *URL link* kustom dari pihak korbannya sedikit pun.
**Answer:** False

### Q3
**Type:** Short Answer
**Question:** Dari rincian anatomi pengklasifikasian taksonomi arsitektur celah peramban 3 varian kategori kerentanan monster manipulatif jaringan serangan *XSS (Stored, Reflected, DOM-based)*, kasta varian klasifikasi manakah yang spesifik menjangkit mengancam eksploitasi aplikasi sepenuhnya lantaran kealpaan kelalaian implementasi arsitektur perutean keamanan di penulisan operasional kodingan tata letak antarmuka skrip klien *Frontend JavaScript Browser Rendering Logic System*, misalnya ketika pemrogram aplikasi klien secara ceroboh mengeksekusi rutinitas modifikasi antarmuka mengandalkan deklarasi rute penyayat injeksi penugasan penanganan *string modifier syntax* eksekutor properti DOM manipulatif semisal fungsionalitas rentan properti kustom modifikasi objek parameter `innerHTML` (yang dieksploitasi menyalurkan payload masukan kotor pengikatan fungsi masukan tak tersaring ke peramban dokumen render)?
**Answer:** DOM-based XSS (DOM XSS).

### Q4
**Type:** Short Answer
**Question:** Dalam skenario demonstrasi peretasan Web, ketika sepotong kerangka skrip antarmuka payload *JavaScript* maut racun terenkripsi modifikasi berhasil dipancarkan masuk pemblokiran validasi jaringan dengan eksekusi pembuktian parameter pengujian modifikasi rute pembongkaran pop-up `alert('1')` tereksekusi pada peramban antarmuka klien pengunjung, tujuan akhir eksploitasi rahasia spesifik target pelacakan pencurian informasi peladen apakah (lazimnya membidik spesifikasi embel informasi parameter identitas kuncian token memori sesi peramban rahasia *browser credential parameter*) yang biasanya secara murni hendak diretas dan dirampas penyadapannya secara diam-diam oleh penganalisis penyerang peretasan sesungguhnya demi mengambil alih akun korbannya?
**Answer:** Cookie (atau spesifiknya parameter *Session Cookie / Token Sesi Autentikasi*).
