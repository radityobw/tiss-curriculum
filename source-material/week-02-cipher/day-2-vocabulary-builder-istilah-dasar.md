## 📖 Materi Inti

### 30 Istilah Wajib Cybersecurity (Bagian 1)

Hari ini kita akan fokus pada kosakata (vocabulary). Jangan dihafal sekaligus, tapi **pahami konteksnya**.

#### 🔴 Kategori: Offensive (Penyerangan & Ancaman)

| Istilah | Konteks / Makna Sebenarnya |
|---------|---------------------------|
| **Vulnerability** | Titik lemah atau celah keamanan pada suatu sistem. (Bukan sekedar "kerentanan"). |
| **Exploit** | Kode atau program yang dibuat secara khusus untuk memanfaatkan *vulnerability*. |
| **Payload** | Bagian dari kode eksploitasi yang melakukan tindakan merusak sesungguhnya (seperti mencuri data atau membuka *backdoor*). |
| **Backdoor** | Metode tersembunyi untuk masuk ke sistem melewati otentikasi normal. |
| **Malware** | *Malicious Software* - perangkat lunak jahat (virus, worm, trojan, ransomware). |
| **Phishing** | Penipuan dengan menyamar sebagai pihak terpercaya untuk mencuri informasi (biasanya lewat email). |
| **Spoofing** | Memalsukan identitas (seperti IP address atau MAC address) agar terlihat sah. |
| **Brute Force** | Mencoba setiap kombinasi password yang mungkin sampai berhasil masuk. |
| **Zero-Day (0-day)**| *Vulnerability* yang baru diketahui oleh publik/pembuat software, sehingga belum ada *patch* (perbaikan)-nya. (Artinya developer punya "nol hari" untuk bersiap). |
| **Breach** | Insiden di mana data rahasia berhasil ditembus atau dicuri oleh pihak luar. |

#### 🔵 Kategori: Defensive (Pertahanan & Pencegahan)

| Istilah | Konteks / Makna Sebenarnya |
|---------|---------------------------|
| **Patch** | Update software yang dirilis untuk memperbaiki *vulnerability* atau *bug*. |
| **Mitigation** | Langkah-langkah untuk mengurangi dampak dari sebuah ancaman atau serangan. |
| **Firewall** | Sistem yang mengatur lalu lintas masuk dan keluar jaringan berdasarkan aturan keamanan. |
| **Encryption** | Proses mengacak data sehingga tidak bisa dibaca tanpa kunci rahasia (*decrypt key*). |
| **Authentication** | Proses membuktikan identitas (contoh: login dengan username & password). |
| **Authorization**| Proses menentukan apa yang boleh dilakukan oleh identitas tersebut (hak akses). |
| **Honeypot** | Sistem palsu yang sengaja dibuat lemah untuk memancing dan mempelajari taktik *hacker*. |
| **Incident Response**| Proses terstruktur dalam menangani pelanggaran keamanan cyber. |
| **Log** | Catatan digital otomatis dari setiap aktivitas yang terjadi di sistem atau jaringan. |
| **Forensics** | Proses mengumpulkan, menganalisis, dan memelihara bukti elektronik pasca-serangan. |

#### 📡 Kategori: Networking & Infrastructure (Dasar Jaringan)

| Istilah | Konteks / Makna Sebenarnya |
|---------|---------------------------|
| **Host** | Setiap perangkat (komputer, server, HP) yang terhubung ke jaringan. |
| **Port** | Titik akhir komunikasi virtual dalam sistem operasi. (Ibarat "pintu" khusus untuk layanan tertentu). |
| **Protocol** | Aturan standar bagaimana data ditransmisikan antar perangkat. |
| **Bandwidth** | Kapasitas maksimal transfer data dalam jaringan pada waktu tertentu. |
| **Latency** | Waktu tunda (delay) perjalanan data dari sumber ke tujuan. |
| **Router** | Perangkat yang menghubungkan dua atau lebih jaringan dan mengarahkan data. |
| **Server** | Komputer/sistem yang menyediakan layanan, data, atau resource ke komputer lain (*client*). |
| **Client** | Komputer atau software yang meminta layanan dari server. |
| **Traffic** | Aliran data di dalam sebuah jaringan. |
| **Proxy** | Server perantara yang meneruskan permintaan dari *client* ke server tujuan. |

> 💡 **Tips Belajar**: Jika kamu sering bermain *game online*, banyak istilah di atas yang mungkin sudah familiar (seperti *latency*, *server*, *client*, *host*). Gunakan pengetahuan itu sebagai batu loncatan!

## 💡 Quiz Kilat

<details>
<summary>❓ Apa perbedaan antara Authentication dan Authorization?</summary>

**Jawaban:** 
- **Authentication**: Membuktikan SIAPA kamu. (Contoh: Menunjukkan KTP atau login pakai password).
- **Authorization**: Menentukan APA YANG BOLEH kamu lakukan. (Contoh: KTP mu dicek, oh kamu mahasiswa, jadi kamu boleh masuk perpustakaan tapi tidak boleh masuk ruang dosen).

</details>

<details>
<summary>❓ Mengapa "Zero-Day" (0-day) vulnerability sangat berbahaya?</summary>

**Jawaban:** Karena *vulnerability* tersebut belum diketahui oleh pembuat *software* (developer), sehingga belum ada **patch** (perbaikan/update) yang tersedia. Hacker bebas menyerang tanpa ada pertahanan pasti dari sistem.

</details>

<details>
<summary>❓ Jika sebuah perusahaan memasang server palsu yang penuh dengan kelemahan untuk menjebak hacker, server tersebut disebut apa?</summary>

**Jawaban:** **Honeypot**. Ini adalah taktik Blue Team untuk mengalihkan perhatian attacker dari server asli, sekaligus mempelajari teknik yang digunakan attacker (*Exploit*, *Payload*, dll).

</details>
